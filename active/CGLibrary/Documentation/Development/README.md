# Development

Эта папка содержит внутреннюю документацию по разработке библиотеки.

Общее правило для development-документов: писать только факты, рабочие правила и прямые указания по процессу. Не писать пустые общие фразы.

## Навигация

- [`../DocumentationConventions.md`](../DocumentationConventions.md)
  Объект: общие соглашения по текстовой документации репозитория.
  Когда использовать: когда нужно сверить формат `.md`-файлов, правила ссылок и требования к кодировке текста.

- [`RepoStructure.md`](./RepoStructure.md)
  Объект: компактный обзор структуры репозитория.
  Когда использовать: когда нужно быстро понять, где находится нужный код, документация или рабочая папка.

- [`BuildAndTestWorkflow.md`](./BuildAndTestWorkflow.md)
  Объект: рабочие правила запуска сборок, тестов и research-runner'ов.
  Когда использовать: когда нужно сверить допустимый build/test workflow и не попасть в ложные file-lock ошибки от параллельных запусков.

- [`CodingConventions.md`](./CodingConventions.md)
  Объект: правила оформления кода и инженерные конвенции.
  Когда использовать: когда нужно сверить требования к стилю кода, именованию и общим правилам изменения API.

- [`XMLAndWorkingFiles.md`](./XMLAndWorkingFiles.md)
  Объект: правила по XML-комментариям и временным рабочим файлам.
  Когда использовать: когда нужно понять, как документировать код, когда писать XML и как создавать и удалять временные заметки.

- [`LibPolytopeFormat.md`](./LibPolytopeFormat.md)
  Объект: рабочее описание формата `LibPolytope`.
  Когда использовать: когда нужно сверить представление данных `LibPolytope` и синхронизировать с ним код.

- [`PolyhedraNaming.txt`](./PolyhedraNaming.txt)
  Объект: рабочая памятка по именованию многогранников.
  Когда использовать: когда нужно сверить исторические или внутренние имена геометрических объектов.
