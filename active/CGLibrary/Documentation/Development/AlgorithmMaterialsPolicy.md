# Algorithm Materials Policy

Документ задаёт правило хранения материалов, которые появляются вокруг алгоритмов `CGLibrary`.

## Главное правило

Материал хранится рядом с активной библиотекой, если он помогает понимать, проверять или развивать текущую реализацию алгоритма.

Материал выносится за пределы активной библиотеки, если он шире текущего кода, относится к статье, внешнему сравнению, старому формату, историческому контексту или большому эксперименту.

## Слои

### Код

Реализация алгоритма живёт в `CGLibrary/`.

Код не должен ссылаться на исследовательские заметки как на обязательную часть выполнения. Если алгоритму нужен входной файл или формат данных, это уже часть контракта и должна быть описана отдельно.

### Tests

`Tests/` содержит быстрые автоматические проверки и тестовую инфраструктуру.

В `Tests/` можно хранить только небольшие входные данные, которые реально нужны для запуска тестов.

Картинки, схемы и поясняющие материалы не должны жить в `Tests/`. Для них используется `Research/<TopicOrAlgorithm>/References/`, а из ближайшего README тестовой папки даётся ссылка.

### Tests/Manual

`Tests/Manual/` содержит только короткие ручные `[Explicit]`-проверки через NUnit runner.

Сюда не относятся:

- постоянные regression-тесты;
- performance-замеры;
- большие исследовательские прогоны;
- локальные данные и заметки.

### Profile

`Profile/` является основным местом для performance-замеров и benchmark-сценариев.

Если старый performance-сценарий лежит в тестах, его нужно перенести в `Profile/` или удалить после сверки с существующими benchmark-ами.

### Research

`Research/` содержит отобранные материалы к текущим алгоритмам библиотеки.

Сюда относятся:

- маленькие воспроизводимые случаи;
- схемы и картинки, помогающие читать код или тесты;
- отобранные заметки о поведении алгоритма;
- важные особые случаи;
- ссылки на связанные тесты, benchmark-и и внешние источники.

Минимальная структура:

```text
Research/<TopicOrAlgorithm>/
  README.md
```

Дополнительные папки создаются только при наличии реальных материалов:

```text
Research/<TopicOrAlgorithm>/
  Cases/
  References/
  Notes/
```

Папки не создаются заранее на будущее. Название темы выбирается по сути содержимого, а не обязательно по имени класса или метода.

`Research/` не заменяет документацию. Если из исследовательских материалов получилось устойчивое объяснение правила, формата или архитектуры, это объяснение переносится в `Documentation/`, а `Research/` остаётся местом для исходных кейсов, картинок и наблюдений.

### Documentation

`Documentation/` содержит устойчивые правила, карты, соглашения и объяснительные тексты.

Документация может ссылаться на `Research/`, но не должна копировать его материалы. Исследовательские картинки и кейсы не переносятся в документацию только ради того, чтобы их можно было процитировать.

### references

Корневой `references/` содержит внешний и общий контекст:

- статьи;
- конспекты внешних источников;
- общую теорию;
- чужие реализации для сравнения;
- большие справочные наборы данных;
- материалы, не привязанные к одному активному алгоритму.

Если внешний материал используется конкретным алгоритмом, в `Research/<TopicOrAlgorithm>/README.md` или в документации даётся ссылка на него.

Чужой код коммитится только при понятной лицензии и явной необходимости. Иначе хранится ссылка на источник или рабочая заметка в `.tmp/`.

### legacy

`legacy/` содержит исторические материалы, старые проекты, старые данные и старые форматы, которые не являются частью активной библиотеки.

Материал из `legacy/` поднимается обратно в активный слой только по отдельному решению.

### .tmp

`.tmp/` содержит временные файлы текущей работы:

- черновики;
- сырые логи;
- промежуточные таблицы;
- неотобранные заметки;
- результаты одноразовых запусков;
- рабочие медиа и артефакты.

Содержимое `.tmp/` по умолчанию не коммитится.

## Что коммитить

Коммитить можно только материалы с понятной долговременной ролью:

- короткие `README.md`;
- маленькие воспроизводимые кейсы;
- отобранные схемы и картинки;
- итоговые наблюдения;
- материалы, на которые ссылаются тесты, документация или `Research`-README.

Не коммитить по умолчанию:

- сырые логи;
- большие результаты запусков;
- промежуточные таблицы;
- неотобранные заметки;
- машинные артефакты;
- материалы без понятной связи с текущей работой.

## Связи между слоями

Связи оформляются ссылками, а не дублированием текста.

- Код содержит реализацию.
- Тесты проверяют поведение.
- `Tests/Manual/` содержит короткие ручные проверки.
- `Profile/` измеряет производительность.
- `Research/` хранит отобранные материалы вокруг текущих алгоритмов.
- `Documentation/` фиксирует устойчивые правила и объяснения.
- `references/` хранит внешний контекст.
- `legacy/` хранит исторический слой.
- `.tmp/` хранит временную работу.

## Текущий пример

Картинки `ConvexIntersectionFigures`, объясняющие взаимное расположение многоугольников для пересечения выпуклых 2D-многоугольников, следует хранить в исследовательском слое алгоритма:

```text
Research/PolygonIntersection2D/References/ConvexIntersectionFigures/
```

Из ближайшего README в `Tests/` нужно дать ссылку на эту папку. Сами картинки не должны оставаться внутри тестового слоя, если они не являются входными данными для запуска тестов.
