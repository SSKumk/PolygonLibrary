# DoubleGeometry Tests

Новая структура тестов для геометрического ядра `double`.

Правила миграции:

1. Переносим тесты строго по одному классу или одной тесно связанной сущности.
2. Для выбранного класса новая структура заполняется полностью в `Tests/DoubleGeometry/...`.
3. При переносе сценарии и покрытие согласовываются с документами из `Documentation/Testing/CoveragePlan/...`.
4. После переноса legacy-файл исключается из активной структуры тестов.
5. Во время миграции не держим в сборке буквальные дубликаты одних и тех же тестов.

Workflow переноса:

1. Выбираем один класс и проверяем, что для него уже есть или создаётся папка в `Documentation/Testing/CoveragePlan/...`.
2. Уточняем сценарии, статусы и `Gaps` по реальному коду, не придумывая контрактов, которых нет в API.
3. Создаём новую папку класса в `Tests/DoubleGeometry/...` и раскладываем тесты по темам, а не одним большим файлом.
4. Переносим и дописываем тесты так, чтобы они закрывали согласованный coverage plan.
5. Синхронизируем ссылки в документации на реальные новые тестовые файлы.
6. Только после этого исключаем legacy-файл из активной структуры тестов, если он был.
7. Проверяем обычную сборку `Tests.csproj` без запуска долгих тестов, если для текущего шага запуск не нужен.

Правило про некорректные входы:

- сценарии вида “caller violated preconditions” не закрепляются тестами автоматически;
- если библиотека не обязана защищать такие случаи в `Release`, это не считается пробелом миграции;
- включаем такие тесты только когда для них явно определён контракт уровня API.

Целевая структура:

- `Infrastructure` — общие ассерт-хелперы, базовые классы, test data.
- `Basics` — базовые геометрические объекты и операции.
- `Polygons` — 2D-полигональные сущности и их вспомогательные объекты.
- `Polyhedra` — полигональные/политопные структуры более высокого уровня.
- `Algorithms` — алгоритмы, использующие базовые геометрические объекты.
