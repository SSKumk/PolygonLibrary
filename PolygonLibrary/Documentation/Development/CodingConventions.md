# Coding Conventions

Этот файл фиксирует общие соглашения по оформлению кода в `CGLibrary`.

## XML Documentation

В библиотеке XML-комментарии пишутся для всего кода, а не только для публичного API.

Это означает:

- XML-комментарии обязательны для `public`, `protected`, `internal` и `private` сущностей.
- Должны быть задокументированы классы, структуры, интерфейсы, перечисления, делегаты, поля, свойства, конструкторы, методы и значимые вспомогательные члены.
- Если член существует как часть алгоритма или инварианта, его назначение должно быть описано даже тогда, когда он имеет `private` уровень видимости.
- Отсутствие XML-комментария рассматривается как незавершённая документация кода.

## Rationale

Для этой библиотеки внутренняя реализация так же важна, как и внешний API:

- алгоритмы и геометрические инварианты требуют явной фиксации;
- private/internal код участвует в сопровождении не меньше, чем public API;
- тестирование идёт снизу вверх, поэтому внутренние контракты тоже должны быть читаемо описаны.
