# Hull Algorithms

## Covered scenarios

- `CONV-001` `QuickHull2D` корректно строит оболочку квадрата при наличии внутренних, граничных и дублирующих точек.
- `CONV-002` `ArcHull2D` строит квадратную оболочку в положительном обходе.
- `CONV-003` `ArcHull2D(sortByPrecision: false)` проходит по ветке процессорного сравнения и сохраняет ту же оболочку на простом наборе.
- `CONV-004` `GrahamHull` materialize-ит обычный ленивый `IEnumerable` и не зависит от повторных `Count()/Min()` по входу.
- `CONV-005` Все три алгоритма корректно обрабатывают пустой набор, одиночную точку и пару точек.
- `CONV-006` Все три алгоритма на коллинеарном наборе оставляют только крайние точки.

## Notes

- Для `GrahamHull` текущий контракт теперь предполагает раннее materialize-ение входа в список, чтобы алгоритм не зависел от повторных `Count()/Min()` по входному `IEnumerable`.
- Это не отменяет ограничений самих LINQ-обёрток: если вызывающий код передаст `Union(...)`, то hash-based логика `Union` сработает ещё до входа в алгоритм.
- В активный слой пока не включены тяжёлые randomized-сравнения между всеми тремя алгоритмами на больших выборках.
