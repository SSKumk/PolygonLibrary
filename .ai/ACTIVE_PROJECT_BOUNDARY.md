# Active Project Boundary

Этот файл фиксирует рабочее решение по границе активного проекта и исторических материалов.

Статус: `draft`

## Рабочая классификация

### Активный проект

- `PolygonLibrary/`

Назначение:

- основная рабочая папка проекта;
- содержит актуальное решение `CGLibrary.sln`;
- содержит ядро `CGLibrary/`, тесты `Tests/`, документацию `Documentation/`, backlog `todo.md` и журнал закрытых задач `done.md`.

Правило:

- обычные изменения кода, тестов, документации и структуры активного проекта делаются здесь;
- перед изменениями читать `PolygonLibrary/README.md` и связанные документы из `Documentation/`.

### Служебный слой работы с агентами

- `AGENTS.md`
- `.ai/`
- `.agents/skills/`

Назначение:

- `AGENTS.md` задаёт стартовые правила для агента;
- `.ai/` хранит рабочие материалы по наведению порядка;
- `.agents/skills/` хранит локальные скиллы репозитория.

Правило:

- эти файлы можно менять в рамках задач по организации работы агентов и документации;
- `.ai/` не должна подменять постоянную проектную документацию в `PolygonLibrary/Documentation/`.

### Внешняя зависимость активного проекта

- `AVLUtils/`

Назначение:

- отдельный проект с AVL-структурами;
- активный `PolygonLibrary/CGLibrary/CGLibrary.csproj` ссылается на `..\..\AVLUtils\AVLUtils\bin\Release\net8.0\AVLUtils.dll`.

Правило:

- не считать `AVLUtils/` частью обычной рабочей области `PolygonLibrary/`;
- не менять без задачи, явно связанной с этой зависимостью;
- при будущей уборке отдельно решить, как фиксировать зависимость: исходниками, бинарником, пакетом или другим способом.

### Reference-материалы

- `Materials/`

Назначение:

- материалы по алгоритмам, статьи, заметки, PDF, TeX и вспомогательные проекты;
- источник внешнего и исторического контекста для алгоритмов.

Правило:

- использовать как справочный слой;
- не менять в обычных задачах по активному проекту без отдельного решения;
- при переносе полезного знания в активную документацию ссылаться на источник или фиксировать связь.

### Legacy-проекты и вычислительные материалы

- `LDG_Convex_2D/`

Назначение:

- отдельный старый слой проектов, вычислений и материалов по линейным дифференциальным играм;
- содержит собственные solution/project-файлы и вычислительные каталоги.

Правило:

- не считать частью активной `PolygonLibrary/`;
- не менять без отдельной задачи по legacy LDG или переносу материалов;
- при необходимости брать из него идеи и данные через явно описанный перенос.

### Исторические копии и старый код

- `Настя/`
- `_Reminiscence/`

Назначение:

- исторические копии старых проектов, тестов, GNUPlot-материалов и старого кода;
- слой для восстановления контекста и сравнения со старой структурой.

Правило:

- считать read-only legacy-материалами;
- не менять, не чистить и не удалять без отдельного решения;
- если оттуда переносится полезный сценарий или правило, перенос фиксировать в активном месте.

### Архивы

- `_Archives/`

Назначение:

- архивные `.7z`-снимки старых состояний `PolygonLibrary` и `AVLUtils`.

Правило:

- не изменять и не удалять в обычном рабочем процессе;
- рассматривать только как исторические снимки;
- любые действия с архивами требуют отдельного решения.

## Общее правило работы

По умолчанию работать только в:

- `PolygonLibrary/`;
- `AGENTS.md`;
- `.ai/`;
- `.agents/skills/`.

Все остальные верхнеуровневые папки считаются неактивными для обычных задач.

Исключение возможно только если пользователь явно называет такую папку или задача отдельно касается legacy, reference-материалов, архивов или внешней зависимости.
