# Navigation README

## Scope

Этот скилл применяется к `README.md`, который служит навигацией по папке, разделу документации, подсистеме или набору связанных файлов.

Не применять к документам, где `README.md` является полноценным описанием алгоритма, формата данных, исследования или пользовательской инструкции. Для таких файлов сначала смотреть локальные правила раздела.

## Related Skills

При создании или правке навигационного `README.md` также использовать `repository-text-style`.

`repository-text-style` отвечает за общий стиль текста: русский язык, ясность, фактичность и отсутствие пустых общих фраз.

Этот скилл отвечает только за навигационную форму `README.md`: назначение раздела, список ссылок, `Объект`, `Когда использовать` и отсутствие пересказа целевых документов.

## Purpose

Навигационный `README.md` должен помогать читателю быстро понять:

1. что находится в разделе;
2. куда идти за нужным правилом, кодом, статусом или справкой;
3. какой файл является источником нужного знания.

Он не должен пересказывать содержимое целевых документов.

## Required Shape

Обычная структура:

```md
# <Название раздела>

Короткое назначение раздела.

## Навигация

- [`File.md`](./File.md)
  Объект: что это за файл, папка или раздел.
  Когда использовать: в какой ситуации туда идти.
```

Если разделу нужны правила, ограничения или статус, добавлять их отдельным коротким блоком после навигации или перед ней.

## Links

Каждая значимая ссылка должна отвечать на два вопроса:

- `Объект:` что это за файл, папка или раздел;
- `Когда использовать:` когда туда идти.

Плохо:

```md
- [`Testing/`](./Testing/)
```

Хорошо:

```md
- [`Testing/`](./Testing/)
  Объект: документация по тестовому покрытию и миграции тестов.
  Когда использовать: когда нужно понять текущее покрытие, статус миграции или правила оформления coverage-документов.
```

## What To Include

Включать только то, что помогает навигации:

- короткое назначение текущей папки или раздела;
- ссылки на ключевые документы и подпапки;
- роль каждого целевого файла;
- ситуацию, в которой читателю нужно открыть целевой файл;
- ссылку на источник правила, если правило уже описано в другом месте.

## What To Avoid

Не добавлять:

- пересказ содержимого целевого документа;
- длинные вступления;
- общие фразы без проверяемого смысла;
- повтор уже зафиксированных правил;
- случайные ссылки без объяснения, зачем они нужны;
- список всех файлов папки, если часть из них не является навигационно важной.

## Duplication Rule

Если правило уже зафиксировано в другом документе, навигационный `README.md` должен ссылаться на него, а не переписывать правило.

Если два навигационных файла начинают объяснять одно и то же, оставить объяснение в более точном месте, а второй файл сделать ссылкой.

## Size

Навигационный `README.md` должен оставаться компактным.

Если раздел разрастается, лучше:

- добавить ссылку на отдельный документ;
- разбить навигацию на несколько коротких тематических групп;
- перенести подробности из README в целевой файл.

## Checklist

Перед завершением проверить:

- файл объясняет назначение раздела;
- навигационные ссылки имеют `Объект` и `Когда использовать`;
- README не пересказывает целевые документы;
- правила не продублированы без необходимости;
- список ссылок не превращён в полный технический дамп папки;
- текст компактный и написан по существу.
