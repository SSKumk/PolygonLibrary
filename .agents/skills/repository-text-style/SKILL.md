# Repository Text Style

## Scope

Этот скилл применяется к текстам, которые сохраняются в репозитории.

## Purpose

Писать текст репозитория так, чтобы читатель мог легко и быстро понять его смысл.

Текст должен быть полезным для человека, который вернулся к проекту позже или передал задачу агенту.

## Language

Писать по-русски по умолчанию.

Английский оставлять без перевода только там, где это технический литерал:

- имена файлов и папок;
- команды;
- имена классов, методов, пакетов и API;
- названия форматов;
- статусы инструментов;
- точные цитаты.

Если английский термин нужен для узнавания привычного названия, сначала дать русский смысл, а английский вариант указать в скобках.

Плохо:

```text
Это prose-документация.
```

Хорошо:

```text
Это связный объяснительный текст.
```

Допустимо:

```text
Это журнал невыполненных задач (`backlog`).
```

## Style

Писать коротко, фактами и по делу.

Избегать:

- общих фраз без проверяемого смысла;
- канцелярита;
- лишних английских слов;
- длинных вступлений перед полезной информацией.

Первая фраза раздела должна объяснять смысл, а не внутреннее состояние работы.

Плохо:

```text
В этом разделе представлена информация по различным аспектам проекта.
```

Хорошо:

```text
Раздел описывает правила оформления документации и порядок обновления проектных заметок.
```

## Checklist

Перед завершением правки проверить:

- текст написан по-русски;
- английские слова оставлены только там, где они нужны;
- первая фраза объясняет смысл;
- нет пустых общих фраз;
- если текст ссылается на файл репозитория, ссылка не противоречит локальным правилам этого файла.
