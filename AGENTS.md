# AGENTS

Этот репозиторий содержит активные проекты `CGLibrary` и `LDG`, внешние зависимости и исторические материалы вокруг них.

## Перед работой

- Основная рабочая папка геометрической библиотеки: `projects/CGLibrary/`.
- Основная рабочая папка LDG-проекта: `projects/LDG/`.
- Внешняя зависимость активного проекта: `dependencies/AVLUtils/`.
- Перед изменениями в активном проекте читать `projects/CGLibrary/README.md`.
- Перед изменениями в LDG-проекте читать `projects/LDG/README.md`.
- Для правил документации читать `projects/CGLibrary/Documentation/DocumentationConventions.md`.
- Для правил разработки читать `projects/CGLibrary/Documentation/Development/README.md`.
- Для структуры репозитория читать `projects/CGLibrary/Documentation/Development/RepoStructure.md`.

## Локальные скиллы

Локальные скиллы лежат в `.agents/skills/`.

Использовать их по ситуации:

- `clear-communication`
  Объект: правила общения с пользователем в чате.
  Когда использовать: при промежуточных статусах, итоговых ответах, объяснениях, отчётах, блокерах, результатах проверки и реакции на раздражение пользователя.

- `repository-text-style`
  Объект: общий стиль текстов, которые сохраняются в репозитории.
  Когда использовать: при создании или правке человекочитаемых текстов в файлах проекта.

- `navigation-readme`
  Объект: правила оформления `README.md`, который служит навигацией по папке, разделу или набору файлов.
  Когда использовать: при создании или правке навигационного README со ссылками на другие документы или подпапки.

- `working-folder-readme`
  Объект: правила оформления `README.md`, который задаёт порядок работы с конкретной папкой.
  Когда использовать: при создании или правке README для временной, архивной, исследовательской, служебной или рабочей папки.

- `delegated-agent-workflow`
  Объект: порядок работы с сабагентами.
  Когда использовать: при сборе материала, исследовании, миграциях, кодовых правках и проверке результата через сабагентов.

## Общие правила

- Писать текстовые файлы только в `UTF-8`.
- Не дублировать правила между документами: если правило уже зафиксировано, ссылаться на него.
- При создании, удалении или переносе смысловых файлов и папок проверять ближайшие навигационные `README.md`.
- Не запускать тесты без явного разрешения пользователя.
- Не менять production-код, если задача сформулирована как уборка документации или структуры.
- Не удалять исторические материалы, архивы и legacy-слои без отдельного решения.
